# 从零搭建个人博客网站（Hugo + GitHub Pages）

> 历时三天，从零开始，最终成功搭建了一个属于自己的个人博客网站。这篇文章记录了我完成这件事的全部正确步骤，希望能给有同样想法的人一些参考。

---

## 前言

我一直想拥有一个属于自己的博客，可以自由地写点东西，记录生活和技术的点滴。

一开始以为这是件很简单的事，但真正动手之后才发现，从环境配置到域名解析，每一步都可能踩坑。好在一路跌跌撞撞，最终还是把这件事做成了。

这篇文章不是那种“一夜学会”的速成教程，而是一个真实新手的实操记录——没有跳过任何一个坑，也没有省略任何一个步骤。如果你也打算从零开始，应该能在这里找到答案。

---

## 一、准备工作

在开始之前，需要准备以下几样东西：

- 一台可以联网的电脑（我用的是 Windows）
- GitHub 账号（用来托管代码和发布网站）
- 一个安静的时间段（建议至少留出两三个小时）

---

## 二、安装 Hugo

Hugo 是一个静态网站生成器，它可以把我们写的 Markdown 文章转换成 HTML 网页，速度非常快。

在 Windows 上，我使用的是 **winget** 命令行工具来安装：

markdown

```powershell
winget install Hugo.Hugo.Extended
```

安装完成后，用以下命令验证是否成功：

markdown

```powershell
hugo version
```

如果能看到版本号，说明安装成功了。

> **注意**：一定要安装 Extended 版本，因为有些主题（比如我后来换的 Reimu）用了 SCSS 功能，普通版本无法编译。

---

## 三、创建博客站点

在电脑上选择一个合适的位置，打开终端（PowerShell），执行：

markdown

```powershell
hugo new site my-blog
cd my-blog
```

这个命令会创建一个名为 `my-blog` 的文件夹，里面是 Hugo 站点的初始结构。

---

## 四、安装主题

Hugo 本身没有样式，需要安装主题来决定博客长什么样。我前后尝试了两个主题：

### 第一个主题：PaperMod（简单干净）

markdown

```powershell
git init
git submodule add https://github.com/adityatelange/hugo-PaperMod.git themes/PaperMod
```

### 第二个主题：Reimu（最终选择）

后来我换了一个更有个性的主题，名字叫 Reimu：

markdown

```powershell
git submodule add git@github.com:D-Sketon/hugo-theme-reimu.git themes/reimu
```

在 `hugo.toml` 中指定主题：

markdown

```toml
theme = 'reimu'
```

---

## 五、本地预览

在项目根目录下执行：

markdown

```powershell
hugo server
```

然后在浏览器中打开 `http://localhost:1313`，就能看到博客的实时预览效果。

> 每次修改内容或配置，保存后浏览器会自动刷新，非常方便。

---

## 六、创建第一篇文章

Hugo 提供了快速创建文章的命令：

```markdown

```powershell
hugo new content posts/我的第一篇文章.md
```

创建后，用记事本打开文章文件，把 `draft: true` 改为 `draft: false`，这样文章才会在页面上显示。

然后就可以用 Markdown 语法写正文了：

```markdown
---
title: "我的第一篇文章"
date: 2026-08-01T14:47:09+08:00
draft: false
---

你好，世界！这是我的第一篇博客文章。
```

---

## 七、GitHub 仓库配置

为了让全世界都能访问到我的博客，我需要把代码托管到 GitHub，并用 GitHub Pages 发布。

### 1. 创建 GitHub 仓库

在 GitHub 上创建一个新仓库，名称必须严格遵守：

```
你的用户名.github.io
```

比如我的用户名是 `panzhengyi12`，所以仓库名就是 `panzhengyi12.github.io`。

### 2. 配置 SSH 密钥（可选，但推荐）

为了安全地推送代码，我配置了 SSH 密钥。生成密钥并添加到 GitHub：

```powershell
ssh-keygen -t rsa -b 4096 -C "你的邮箱"
```

将公钥（`~/.ssh/id_rsa.pub` 的内容）添加到 GitHub Settings → SSH and GPG keys。

### 3. 关联本地和远程仓库

```powershell
git remote add origin git@github.com:你的用户名/你的用户名.github.io.git
```

---

## 八、配置 GitHub Actions 自动部署

每次写新文章都要手动构建并上传，太麻烦了。我通过 GitHub Actions 实现了自动化：每次 `git push`，GitHub 会自动构建 Hugo 站点并发布。

在 `.github/workflows/hugo.yaml` 中配置工作流，指定 Hugo 版本、构建命令和发布路径。

> 特别注意：如果主题使用了 SCSS，需要下载 Hugo Extended 版本，而不是普通版本。这一点花了我很长时间才搞明白。

---

## 九、配置主题信息

在 `config/_default/params.yml` 中修改网站的基本信息：

```yaml
author: panzhengyi
email: panzhengyi@gmail.com
description: "桃李不言下自成蹊"
avatar: "/images/avatar.jpg"
```

### 头像路径的坑

头像这个问题困扰了我很久。一开始我把头像放在 `static/images/avatar.jpg`，在 `params.yml` 中写成 `avatar: "images/avatar.jpg"`，但线上一直不显示。

后来发现 Reimu 主题模板会在头像路径前自动添加 `/avatar/` 前缀，导致实际请求的是 `/avatar/images/avatar.jpg`。

最终我用了最直接的方法：把图片也放到 `static/avatar/images/avatar.jpg`，让主题模板能直接找到。

## 十、日常写作流程

博客搭建完成之后，每次发布新文章的步骤非常简洁：

### 1. 创建文章

```powershell
hugo new content posts/新文章标题.md
```

### 2. 编辑文章内容

用任何文本编辑器打开上一步生成的文件，把 `draft: true` 改为 `draft: false`，然后用 Markdown 语法写作。

### 3. 推送到 GitHub

```powershell
git add .
git commit -m "发布新文章：新文章标题"
git push
```

### 4. 等待自动部署

推送后，GitHub Actions 会自动构建并部署，约 1~3 分钟后刷新网页就能看到新文章了。

## 十一、遇到的问题与解决

### 1. Git 推送被拒绝

```
ERROR: Repository not found.
```

检查仓库名是否和用户名一致。GitHub Pages 的仓库名必须严格等于 `你的用户名.github.io`。

### 2. Hugo 无法识别主题

```
WARN found no layout file for "html" for kind "section"
```

检查 `hugo.toml` 中的 `theme` 名称是否和 `themes/` 文件夹名完全一致。

### 3. 头像不显示

主题模板在路径前加了 `/avatar/` 前缀。解决方法：把图片同时放在 `static/images/avatar.jpg` 和 `static/avatar/images/avatar.jpg`。

### 4. SSH 连接失败

```
Recv failure: Connection was reset
```

国内访问 GitHub 有时不稳定，可以开启 VPN 或使用 SSH 方式连接。

---

## 十二、总结

从零开始搭建一个个人博客，看似简单，实际操作中会遇到各种细节问题。但正是这些“坑”让人收获最多。

总结一下这次学习到的关键经验：

1. **耐心是最重要的工具**。遇到错误不要慌，仔细看报错信息，大多数时候问题就在那几行字里。

2. **版本控制要养成习惯**。每一次修改后及时 `git add`、`git commit`、`git push`。

3. **善用 GitHub Actions**。自动部署省去了很多重复工作，让写博客真正专注于内容本身。

4. **Markdown 是写作的好朋友**。不需要像写 Word 一样调整格式，只需要关注内容，剩下的交给 Hugo。

5. **解决问题也是一种学习**。头像路径的问题让我理解了 `static` 目录的工作原理，也让我学会了怎么在主题模板里找代码。
